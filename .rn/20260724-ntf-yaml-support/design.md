# NTF解説書 章構成設計

## 1. 読者と構成

読者は2種類。両者に共通する前提は独立させ、3部構成とする。

| 読者 | 知りたいこと | 参照する部 |
|---|---|---|
| アーキテクト | NTFの全体構造・仕組み・設定 | 第1部、第2部 |
| アプリ開発者 | テストの書き方 | 第1部、第3部 |

```
テスティングフレームワーク
├── テスティングフレームワークとは      第1部・概念（両読者の共通前提）
├── 導入と設定                          第2部・アーキテクト向け
└── テストの実装方法                    第3部・アプリ開発者向け
```

読者の振り分けは最上位 `index.rst` の本文で行う。

---

## 2. 第1部 テスティングフレームワークとは

**1ページ。** FW解説書の `Nablarchアプリケーションフレームワークとは`（`ja/application_framework/application_framework/nablarch/`）の構成に倣う。

| セクション | 記載内容 |
|---|---|
| 全体像 | NTFの位置づけ。JUnitベースであること。Nablarchに特化したテスト補助機能を提供すること |
| アーキテクチャ | 自動テストフレームワークの構成。テストクラスの継承構造。リクエスト単体テストがハンドラキューを通す仕組み |
| テストの種類 | クラス単体テスト / リクエスト単体テスト / 取引単体テストの違いと使い分け |
| テストデータ | テストデータを外部ファイル化する意味。セットアップデータと期待値。データブロックの考え方 |
| 対象範囲 | 対応する処理方式の一覧。対応しないもの（Jakarta Batch、マルチスレッド機能） |
| 稼動環境 | JUnit 4 / JUnit 5、Java・Jakarta EEの要件 |

### 「テストの種類」に置く対比

読者が自分の書くべきテストを判断できるよう、以下を示す。

| テストの種類 | 実行方法 | テスト範囲 | 備考 |
|---|---|---|---|
| クラス単体テスト | JUnitで自動実行 | クラス単体 | エンティティ、コンポーネント |
| リクエスト単体テスト | JUnitで自動実行 | 1リクエスト（ハンドラキューを通す） | 本番に近い構成でテストできる |
| 取引単体テスト | 手動操作 | 複数リクエストにまたがる業務の流れ | APサーバへのデプロイが必要。エビデンスは画面ハードコピー・DBダンプ |

取引単体テストが自動テストではないことを明示する。

## 3. 第2部 導入と設定

暫定構成を以下とし、**ページ分割はマッピング作成後の文量集計で確定する。**

```
導入と設定
├── 共通設定                    テストデータの配置、日時固定、採番、トランザクション等
├── クラス単体テストの設定
├── リクエスト単体テストの設定   処理方式ごと
├── テストデータの形式          Excel / YAML の比較と使い分け、プロジェクト内での統一方針
├── JUnit 5用拡張機能
└── マスタデータ復旧機能
```

### 記載範囲

| 記載する | 記載しない |
|---|---|
| 主なクラスとリソース | テストソースコードの実装例 |
| 構造（クラスの役割と関係） | テストデータの記述例 |
| コンポーネント設定ファイルの設定項目一覧 | 目的別のAPI使用方法 |
| 設定ファイルの記述例 | |

「使い方」に該当するものは第3部に置き、第2部からは `:ref:` で参照する。

## 4. 第3部 テストの実装方法

```
テストの実装方法
├── テストデータの書き方                            1ページ
├── テストデータの記載例                            1ページ
├── クラス単体テスト
│     ├── エンティティ単体テスト
│     └── コンポーネント単体テスト
├── リクエスト単体テスト
│     ├── ウェブアプリケーション
│     ├── RESTfulウェブサービス
│     ├── HTTPメッセージング
│     ├── Nablarchバッチアプリケーション
│     ├── MOMによるメッセージング
│     └── テーブルをキューとして使ったメッセージング
└── 取引単体テスト
      （処理方式ごと。構成はマッピング作成後の文量集計で確定する）
```

### テストデータの2ページ

| ページ | 役割 |
|---|---|
| テストデータの書き方 | 記法の仕様。どう書けばどう解釈されるか |
| テストデータの記載例 | 用途別の実例。Excel と YAML の対比で示す |

**それぞれ1ページにまとめる。** 開発者が記法を調べるとき、テーブル・ファイル・メッセージングを同じページ内で探せる状態にする。ページを跨がせない。

**「書き方」から「記載例」へのリンクを必須とする。** 仕様を読んだ読者が対応する実例に到達できること。

## 5. 処理方式の名称

FW解説書の正式名称を使用する。

| 名称 | FW解説書の所在 | NTF対象 |
|---|---|---|
| ウェブアプリケーション | `application_framework/web/` | ○ |
| RESTfulウェブサービス | `application_framework/web_service/rest/` | ○ |
| HTTPメッセージング | `application_framework/web_service/http_messaging/` | ○ |
| Nablarchバッチアプリケーション | `application_framework/batch/nablarch_batch/` | ○ |
| Jakarta Batchに準拠したバッチアプリケーション | `application_framework/batch/jsr352/` | × |
| MOMによるメッセージング | `application_framework/messaging/mom/` | ○ |
| テーブルをキューとして使ったメッセージング | `application_framework/messaging/db/` | ○ |

Jakarta Batch は対象外。第1部「対象範囲」で明示する。

### テーブルをキューとして使ったメッセージング

**章として立てる。** 読者は章見出しを探して辿り着くため、独立した見出しを設ける。

**中身は導線のみとする。** 「Nablarchバッチアプリケーションと同じ方法でテストする」旨と、Nablarchバッチアプリケーションの章への `:ref:` 参照だけを記載する。コード例・テストデータ例は記載しない。

## 6. 作業方針

### マッピングを唯一の基準とする

作成するページの内容は、事前に作成するマッピングリストに従う。**マッピングにない記述を追加しない。マッピングにある記述を落とさない。**

マッピングの粒度はセクション（L3相当）単位とする。

### 白紙から作成する

既存ファイルを部分的に編集する方式は採らない。既存のNTF解説書を削除してから、マッピングに基づいて1ページずつ作成する。削除後も develop ブランチで元の内容を参照できる。

### 1ページごとにレビューする

1ページ作成するごとにレビューを行い、承認を得てから次ページへ進む。
