============================
テストデータの形式
============================

テストデータは Excel または YAML ファイルで記述できる。ここでは両形式の概要・違い・使い分けの指針について説明する。

テストデータの構造（データブロックの種別・識別子など）は :ref:`ntf_testdata_overview` を参照。

---------------------------
Excel 形式
---------------------------

概要
====

テストデータを ``.xls`` ファイル（Excel ブック）に記述する。テストクラスと同名の1ブックを用意し、テスト用途ごとにシートを分けて記述する。

.. code-block:: text

    src/test/java/com/example/
      FooTest.xls
        ├── case01  ← シート
        └── case02  ← シート

各シートのセルを**文字列書式**で記述する。数値・日付書式の動作は保証されない。

記述例
------

.. code-block:: text

    LIST_MAP=testShots
    | no | description        | expectedStatusCode |
    | 1  | 正常に処理されます | 0                  |

    SETUP_TABLE=USER_MASTER
    | USER_ID | USER_NAME |
    | user001 | テストユーザ |

---------------------------
YAML 形式
---------------------------

概要
====

テストデータを YAML ファイルに記述する。テストクラスと同名のディレクトリを用意し、各ファイルが Excel の1シートに相当する。

.. code-block:: text

    src/test/java/com/example/
      FooTest/
        ├── case01.yaml  ← ファイル
        └── case02.yaml  ← ファイル

YAML ファイルは **YAML 1.2** に準拠する。YAML 1.1 との主な違いとして、 ``yes`` / ``no`` / ``on`` / ``off`` は真偽値ではなく文字列として扱われる。値は必ず**ダブルクォートで囲む**。

記述例
------

.. code-block:: yaml

    list_maps:
      - id: testShots
        rows:
          - no: "1"
            description: "正常に処理されます"
            expectedStatusCode: "0"

    setup_tables:
      - table: USER_MASTER
        rows:
          - USER_ID: "user001"
            USER_NAME: "テストユーザ"

---------------------------
Excel と YAML の比較
---------------------------

以下に両形式の主な違いを示す。

.. list-table::
   :header-rows: 1
   :widths: 20 40 40

   * - 項目
     - Excel
     - YAML
   * - ファイル構成
     - テストクラスと同名の ``.xls`` ブック（複数シートで管理）
     - テストクラスと同名のディレクトリ（複数 ``.yaml`` ファイルで管理）
   * - 読み込み単位
     - 1シート
     - 1ファイル
   * - データブロック種別の指定方法
     - シート先頭セルに ``種別=識別子`` を記述（前方一致）
     - 専用トップレベルキーに記述（例: ``setup_tables:`` ）
   * - 値の記述
     - セルを文字列書式で記述
     - ダブルクォートで囲む
   * - バージョン管理との親和性
     - バイナリ形式のため差分確認が難しい
     - テキスト形式のため差分確認が容易
   * - ツール依存
     - Excel（または互換ソフト）が必要
     - テキストエディタで編集可能
   * - 空ファイル時の挙動
     - 空シートは存在しないシート扱い
     - 空ファイル（0バイト）は空データ扱い（エラーにならない）

-----------------------------
使い分けの指針
-----------------------------

以下の観点で形式を選択する。

新規プロジェクトでは YAML 形式を推奨する。テキスト形式であるためバージョン管理との親和性が高く、差分レビューが容易である。

既存の Excel 形式のテストデータが存在するプロジェクトでは、そのまま Excel を継続使用できる。YAML への移行は任意である。

どちらの形式を使用する場合も、テストデータの記述仕様（データブロックの種別・構造・値の書き方）は共通である。詳細は :ref:`ntf_testdata_overview` 以降の各ページを参照。

----------------------------
プロジェクト内での統一方針
----------------------------

1つのプロジェクト内で Excel と YAML を混在させることは技術的には可能だが、保守性の観点からいずれか一方に統一することを推奨する。混在させる場合は、テストクラスごとにどちらか一方を使用し、同一テストクラスで両形式を同時に使用することはできない。
