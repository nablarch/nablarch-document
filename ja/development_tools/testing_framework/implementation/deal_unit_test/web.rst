取引単体テスト（ウェブアプリケーション）
==================================================

.. contents:: 目次
  :depth: 3
  :local:

ウェブアプリケーションの取引単体テストは、テスト対象のアプリケーションをアプリケーションサーバにデプロイし、手動で画面を操作して実施する。

機能概要
--------------------------------------------------

同期応答メッセージ送信を伴う場合は、テスティングフレームワークが提供するモックアップクラスを使用する。詳細は\ :ref:`取引単体テスト（MOMによるメッセージング） <deal_unit_test_mom>`\ を参照。HTTPメッセージ送信を伴う場合は\ :ref:`取引単体テスト（HTTPメッセージング） <deal_unit_test_http_messaging>`\ を参照。

使用方法
--------------------------------------------------

実施するテストごとに、次の手順を繰り返す。二重サブミット防止機能を使用している場合は、その動作も確認する。

テストを準備する
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
テストの準備として次を行う。

* データベースにデータを投入する。
* アプリケーションをデプロイする。
* アプリケーションサーバを起動する。

テストを実施する
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
あらかじめ定めたテストの内容に従ってアプリケーションを操作する。

.. tip::
  エビデンスのうちDBダンプはテスト実行前のものが必要であるため、テストを実施する前に取得する。

テスト結果のエビデンスを取得する
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
次のエビデンスを取得する。

* 画面ハードコピー
* DBダンプ（テスト実行前および実行後）

二重サブミット防止機能を確認する
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
取引単体テストで確認するのは、二重サブミット防止機能のクライアントサイドの動作である。サーバサイドの動作の確認方法と、リクエスト単体テストと取引単体テストで確認内容が分かれる理由は\ :ref:`リクエスト単体テスト（ウェブアプリケーション） <request_unit_test_web>`\ を参照。

この確認は、テストの実施とは別に次の手順で行う。

* アプリケーションサーバをデバッグモードで起動する。
* テスト対象のリクエストに対応するアクションの処理に、ブレークポイントを設定する。
* 画面で、テスト対象のリクエストを送信するボタンを選択する。
* ブレークポイントで処理を止めた状態で同じボタンをもう一度選択し、リクエストが送信されないことを確認する。
