リクエスト単体テストの設定（MOMによるメッセージング）
=====================================================

.. contents:: 目次
  :depth: 3
  :local:

機能概要
--------------------------------------------------
MOMによるメッセージングのリクエスト単体テストは、外部のMOMを用意せずに実施する。メッセージ受信のテストでは、テストの実行中だけJVM内で動く内蔵のメッセージングサーバをメッセージングプロバイダとして登録する。同期応答メッセージ送信のテストでは、キューに接続する代わりに、テストデータにもとづいて要求電文の検証と応答電文の返却を行うプロバイダに差し替える。フレームワーク制御ヘッダのフィールド名を変更しているプロジェクトは、その名前を設定する。テストの実装方法は\ :ref:`リクエスト単体テスト（MOMによるメッセージング） <request_unit_test_mom>`\ を参照。

使用方法
--------------------------------------------------

メッセージ受信用のメッセージングプロバイダを登録する
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
同期応答メッセージ受信・応答不要メッセージ受信のテストでは、テスティングフレームワークがテストデータから作成した要求電文をキューに送信し、同期応答メッセージ受信ではその応答電文をキューから受信して検証する。このキューには、テストの実行中だけ\ JVM\ 内で動作する内蔵のメッセージングサーバを使う。外部のMOMを用意する必要はない。

テスト用のコンポーネント設定ファイルに、内蔵のメッセージングサーバへ接続する\ ``EmbeddedMessagingProvider``\ を登録する。コンポーネント名は\ ``messagingProvider``\ 固定である。テスティングフレームワークはテストショット一覧の\ ``diConfig``\ に指定された設定ファイルからこの名前でプロバイダを取得するため、別の名前で登録すると、テストの実行時に例外が発生する。

キュー名は、要求電文が\ ``TEST.REQUEST``\ 、応答電文が\ ``TEST.RESPONSE``\ で固定されており、変更できない。\ ``queueNames``\ には、この2つをこの名前で記述する。

.. code-block:: xml

  <!-- 内蔵のメッセージングサーバに接続するメッセージングプロバイダ -->
  <component name="messagingProvider"
             class="nablarch.test.core.messaging.EmbeddedMessagingProvider">
    <property name="queueNames">
      <list>
        <value>TEST.REQUEST</value>
        <value>TEST.RESPONSE</value>
      </list>
    </property>
  </component>

同期応答メッセージ送信用のメッセージングプロバイダに差し替える
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
同期応答メッセージ送信のテストでは、キューへのアクセスは行われない。要求電文のアサートと応答電文の生成・返却は、テスティングフレームワークが提供する\ ``RequestTestingMessagingProvider``\ が行う。テスト用のコンポーネント設定ファイルに、次のとおり登録する。

.. code-block:: xml

  <!-- リクエスト単体テスト用のメッセージングプロバイダ -->
  <component name="messagingProvider"
             class="nablarch.test.core.messaging.RequestTestingMessagingProvider"/>

コンポーネント名には、環境設定ファイルの\ ``messageSender.<リクエストID>.messagingProviderName``\ に指定した名前を使用する。リクエストIDごとの設定を持たない場合は、\ ``messageSender.DEFAULT.messagingProviderName``\ に指定した名前を使用する。本番用のコンポーネント設定ファイルと同じ名前で登録することで、テスト用のプロバイダに置き換わる。上書きの記述は、本番用のコンポーネント設定ファイルの読み込みより後に置く。

.. important::

  この差し替えを行わないと、要求電文が実際のキューへ送信され、テストショット一覧の\ ``expectedMessage``\ に記述した要求電文の期待値との照合が成立しない。

フレームワーク制御ヘッダのフィールド名を指定する
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
同期応答メッセージ受信・応答不要メッセージ受信のテストで、\ :ref:`フレームワーク制御ヘッダのフィールド名 <testdata_notation-messaging_data>`\ をデフォルトから変更している場合は、環境設定ファイルに\ ``reader.fwHeaderfields``\ を設定し、フィールド名をカンマ区切りで指定する。指定した名前はデフォルトのフィールド名に追加されるのではなく、デフォルトのフィールド名をすべて置き換える。名前を変更していないフィールドも含めて、使用するフィールド名をすべて列挙する。値に空白を含めると、空白も含めてフィールド名として扱われるため、カンマの前後に空白を入れない。

.. code-block:: properties

  # 使用するフレームワーク制御ヘッダのフィールド名を、すべてカンマ区切りで列挙する。
  reader.fwHeaderfields=requestId,addHeader

.. important::

  この設定が必要なのは、\ Excel\ 形式のテストデータの場合である。\ YAML\ 形式では\ ``fw_header:``\ に記載したキーがすべてフレームワーク制御ヘッダとして扱われるため、この設定は使用されない。同期応答メッセージ送信のテストでも、この設定は使用されない。
